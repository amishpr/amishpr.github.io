# amishprajapati.com / amishp.com

Personal site for Amish Prajapati. React 19 + Vite + TypeScript, prerendered to static HTML and hosted on GitHub Pages. 

## Change the content

Everything on the page lives in **`src/content.ts`**: text, links, the headline, stats,
roles and bullets, projects, skills, the settings for each experience app, and the SEO
title and description.

| To change | Edit |
|---|---|
| Any text or link | `src/content.ts` |
| Colors | `site.palette` in `src/content.ts`: `"emerald"`, `"cobalt"`, `"navy"`, `"mint"`, or `"pine"` |
| Headshot or project screenshots | Put a .jpg or .png in `public/images/`, run `npm run webp`, set `person.photo` or `projects[].image` to `"/images/<file>.webp"`, then move the original out of `public/` (it would ship otherwise) |
| Domain | `site.url` (the `CNAME` file is generated from it) |
| Project screenshots, automatically | `npm run screenshots` captures each project's live `url` (1280x800, dark theme) and saves it to the project's `image`. Options: `-- --light`, `-- ledger` (one project), `-- --out=preview` (save to `preview/` first to compare). Then `npm run build` |
| Link preview image | `npm run build && npm run og && npm run build` (rewrites `public/og.png` from the hero) |
| Favicon | `public/favicon.ico` (16, 32, 48px) and `public/icon-192.png`; `public/apple-touch-icon.png` for iPhone home screens |

Before pushing, `npm run verify` is the quickest way to know nothing broke.
`npm run build` stops with an error that names the problem if a field is misspelled,
missing, or not one of the allowed values. `npm test` also checks that every result
points at a real role, every image path exists in `public/`, and the content has no em or en dashes.

## Commands

```sh
npm install          # once
npm run dev          # local dev server with live reload, http://localhost:5173
npm test             # logic and content checks
npm run build        # type-check, build, and prerender the site into docs/
npm run preview      # serve docs/ at http://localhost:4173, as GitHub Pages will
npm run webp         # convert .jpg/.png in public/images/ to .webp
npm run screenshots  # re-screenshot every project with a live url (see below)
npm run verify       # build, then check the site in a real browser: errors, phone layout, light/dark, all five apps
npm run check-links  # try every link in content.ts and list broken or moved ones
npm run lighthouse   # build, then Lighthouse scores for phone and desktop (add `-- <url>` to score the live site)
npm run og           # regenerate public/og.png (needs `npx playwright@1.48 install chromium` once)
```

## Deploy

Push to `master`. `.github/workflows/deploy.yml` runs the tests, builds the site into `docs/`,
and publishes `docs/` to GitHub Pages. The live site is built from the source in that commit,
so it is right even if you forgot to run `npm run build` first.

`docs/` is also committed, so the repo always holds a copy of the built site. Run
`npm run build` before committing to keep it current. Don't edit `docs/` by hand; the
next build overwrites it (VS Code opens it read-only).

## How it works

| File | Role |
|---|---|
| `src/content.ts`, `src/types.ts` | Content and its shape |
| `src/palettes.ts` | The five color palettes (light and dark) |
| `src/App.tsx`, `src/Results.tsx` | Page sections |
| `src/demos/` | The five experience apps (payroll, ads, maze, bank, e2e) |
| `src/lib/sim.ts` | Pure logic for the apps: seeded RNG, maze, BFS, ad scoring (tested in `sim.test.ts`) |
| `src/lib/motion.ts` | Scroll reveals, count-ups, tweens; all respect reduced motion |
| `src/seo.ts` | Head tags, JSON-LD, robots.txt, sitemap.xml, CNAME, 404.html |
| `scripts/prerender.mjs` | Renders the page to HTML after the build |
| `scripts/webp.mjs`, `scripts/screenshots.mjs`, `scripts/og-image.mjs` | Image conversion, project screenshots, link-preview image |
| `scripts/verify.mjs`, `scripts/check-links.mjs`, `scripts/lighthouse.mjs` | Browser check, link check, Lighthouse scores |
| `docs/` | The built site (generated by `npm run build`) |
| `.vscode/` | Editor settings, recommended extensions, and Run and Debug launchers |
| `src/styles/` | CSS ported from the mockup |
